  no restart, no reconfiguration. Only the NAME was repointed.

WHY TLS DID NOT BREAK
  The certificate is issued to the name app.cn_team.test, not to a machine or
  an IP. Both edges present the same certificate, and the client validates the
  name it asked for. This is the whole reason DNS-based migration is possible
  without reissuing anything.

INTERACTION WITH EXTENSION C (found and fixed during this run)
  The backend firewall originally allowed only Mac 2. The moment traffic moved
  to the standby, the standby would have been firewalled out of the backends
  and returned 502 for everything -- Extension C would have silently broken
  Extension E. The pf rules were changed to allow the EDGE TIER (both the
  primary and the standby), which is how a real security group is written:
  it allows the load-balancer tier, not one specific load-balancer host.
  Verified after the change: backends still time out from a client, and the
  standby can reach them.

REMAINING SINGLE POINT OF FAILURE, REVISITED
  This makes the edge RECOVERABLE, not redundant. The cutover is manual and
  is bounded by the DNS TTL. True HA would publish several edges under one
  name, or use a floating IP a standby claims automatically.
