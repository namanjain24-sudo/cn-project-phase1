Both resolvers return an IDENTICAL record and an IDENTICAL TTL for both names.
That matters more than simply having a second server: if the two disagreed,
failover would quietly send clients to a different machine, which is worse
than having no backup at all. Both configs are generated from config/ips.env,
so they cannot drift apart by accident.

GETTING HERE REQUIRED A FIX (worth explaining in the viva):
  Mac 3 is an MDM-managed machine. dnsmasq served its own loopback but was
  unreachable from the LAN, and the macOS Application Firewall refused to be
  changed from the command line:
      Firewall settings cannot be modified from command line on managed Mac computers.
  The GUI's add button was locked too. Running dnsmasq in the FOREGROUND made
  macOS raise its normal 'accept incoming connections?' prompt, which could be
  approved -- after which the backup resolver became reachable across the LAN.

  Diagnostic point: the backend on TCP 3001 was reachable from Mac 1 the whole
  time, so the host and the network were never in question. A TIMEOUT on one
  port while another port on the SAME host answers means a filter, not a dead
  service -- refused would have meant nothing was listening.
